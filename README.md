# Sik-Gu 프론트 (확인용)

피그마 `Sik-Gu` 와이어프레임을 바탕으로 만든 React 웹입니다. 백엔드(SIKGU-BACKEND)의 실제 API에 붙어서 동작을 확인하는 용도예요.

- React 18 + TypeScript + Vite, 실시간 채팅은 `@stomp/stompjs`
- 백엔드에 CORS 설정이 없어서, 개발 서버(5173)가 `/api`, `/images`, `/ws-stomp`를 백엔드(8080)로 전달합니다 (`vite.config.ts`)

## 실행 순서

필요한 것: Docker Desktop, Node.js 18 이상

**1) 백엔드 (DB·Redis·서버를 Docker로 한 번에)** — [Sik-Gu/Backend](https://github.com/Sik-Gu/Backend)의 `junbin-chatting` 브랜치, `Web` 폴더에서
```powershell
copy .env.example .env      # 처음 한 번: JWT_SECRET, POSTGRES_PASSWORD 를 아무 랜덤 문자열로 채우기
docker compose --profile app up -d --build
```
처음에는 이미지 빌드로 몇 분 걸립니다. `docker compose --profile app logs -f app` 에 `Started WebApplication` 이 보이면 준비 끝.
DB 테이블과 **체험용 계정 3개·공구 2개가 자동으로 만들어집니다** (아래 표). 끄기: `docker compose --profile app down`

> 백엔드 코드를 고치면서 쓸 때는 `docker compose up -d`(DB·Redis만) 후 `SPRING_PROFILES_ACTIVE=demo` 로 `gradlew bootRun` 해도 됩니다.

**2) 프론트** — 이 저장소 폴더에서
```powershell
npm install   # 처음 한 번
npm run dev
```
브라우저에서 http://localhost:5173

## 확인 시나리오 (새로 가입해서 처음부터)

위 체험용 계정 대신 직접 가입해서 전체 흐름을 볼 때의 순서입니다. 백엔드 `.env`에 `MAIL_HOST`가 비어 있으면 인증코드가 메일 대신 **백엔드 로그**에 찍힙니다 (`docker compose --profile app logs app`).

로그인은 브라우저에 유지돼요(localStorage + Refresh Token 자동 재발급). 새로고침·새 탭·브라우저를 다시 열어도 로그아웃 전까지 그대로예요. 대신 같은 브라우저의 탭은 같은 계정을 쓰므로, **A와 B를 동시에 쓰려면 일반 창과 시크릿 창(또는 다른 브라우저)** 에서 각각 로그인하세요. 두 계정의 집 좌표가 **1km 안**이어야 서로의 공구가 보입니다.

| # | 누가 | 할 일 | 확인할 것 |
|---|---|---|---|
| 1 | A | 회원가입: 학교 메일 → 인증메일 발송 → 코드 입력 → 비밀번호 → 동네(흑석동) | 메일 도착(정크함 포함), 랜덤 닉네임, 대학 이름이 마이페이지에 표시 |
| 2 | B | 다른 학교 메일(또는 같은 학교 다른 주소)로 같은 과정, 동네 흑석동 | `gmail.com` 등은 `AUTH4001`로 거절 |
| 3 | A | 포인트 → 30,000 충전 → 결제창에서 **결제 성공** | 잔액 증가, 거래 내역 `충전` |
| 4 | A | 같은 화면의 **같은 주문번호로 한 번 더 승인** | 잔액이 또 늘지 않음 (멱등) |
| 5 | A | 충전 → **결제 실패** / **금액 조작 시도** | `POINT5021` / `POINT4001`, 잔액 그대로 |
| 6 | A | + 공구 열기: 6단위, 29,040원, 내 몫 2단위 | 내 몫 9,680P 결제(보류), 채팅방 생성 |
| 7 | B | 홈에서 A의 공구 → 1단위 참여 (포인트 없으면 `POINT409` → 충전) | B 잔액 차감, A 화면 채팅에 "○○님이 참여했어요" |
| 8 | A·B | 채팅방에서 메시지 주고받기 | 새로고침 없이 바로 보임, 안 읽은 수 |
| 9 | B | 참여 취소 | 전액 환급, 채팅방에서 퇴장(이후 메시지 안 옴) |
| 10 | B | 다시 4단위 참여(남은 단위 전부) | 자동 **모집완료** |
| 11 | A | 나눔 장소 제안 → B 동의 → A 영수증 사진 등록 | 주문완료, 채팅에 안내 |
| 12 | A | 배송 시작 → 나눔 일시 정하기 | 나눔 진행, A는 자동 수령 |
| 13 | B | 받았어요 | **정산완료**: A에게 29,040P 정산, 보류 0, 채팅방 종료 |
| 14 | A·B | 상세에서 후기 남기기 | 후기 저장, 마이페이지 별점 |

에러가 나면 화면 오른쪽 아래에 백엔드 에러 코드(예: `POINT409`)가 같이 떠서 어떤 규칙에 걸렸는지 바로 알 수 있어요.

## 피그마와 다르게 만든 부분 (백엔드·명세 기준을 따름)

- 진행 단계: 피그마의 8단계 중 **'결제 진행중'·'수령 확인'** 은 지금 상태값에 없어 6단계로 표시 (참여 즉시 결제 · BR-20)
- 거리 필터: 피그마 1km/3km/5km → 백엔드 기준 **500m/1km**
- 카테고리: 피그마의 '배달음식' 없음 (백엔드: 식품·생활용품·생필품·기타)
- 포인트 '인센티브' 필터 없음 (D11로 폐지)
- 동네 설정: 카카오맵 SDK 키가 없어 **좌표 직접 입력/현재 위치 → 백엔드가 OpenStreetMap Nominatim으로 동 이름 조회**(동 이름은 수정 불가)
- 충전: 실제 PG 결제창 대신 **가짜 결제창**에서 성공·실패·금액 조작을 고를 수 있음
- 아직 없는 화면: 03-F 수령 문제 문의
- 08-B 신고: 백엔드는 사람만 신고받아서 피그마의 '게시글 유해함' 사유는 빼고 채팅 비속어·거래 중 규칙 위반·기타 3가지만 둠. 모달 대신 `/report` 페이지
